Behaviour before the fix, reproduced in memory with a stubbed urlopen:
  A 2xx reply of [], null, "ok" or 3 was returned unchanged, and the
  caller's .get("code") raised AttributeError.
  A sign-in reply of {"code": 0} without a result raised KeyError: 'result'.
  main() catches neither, so the app process stopped.

After the fix:
  A 2xx reply that is not a JSON object reads as code -1 (transient). A 2xx
  JSON object passes through unchanged.
  A code 0 sign-in reply without a token and user id is not a sign-in. It
  reads as code -1 (transient), and the reply, which can hold a partial
  session token, is neither kept nor logged.

Deliberate regressions applied only in memory: 3/3 caught
  Return non-object 2xx JSON unchanged: validator fails.
  Index the sign-in result without the shape check: validator fails.
  Keep the raw code 0 sign-in reply: validator fails.
